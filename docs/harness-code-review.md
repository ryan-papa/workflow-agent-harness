# Harness: 코드 리뷰 기준

## ⛔ 실행 주체

본 기준의 코드 리뷰는 **반드시 메인 런타임의 서브에이전트**(Claude-Lead=Agent 툴 `subagent_type=general-purpose` / Codex-Lead=`spawn_agent`)가 수행한다. 메인 에이전트가 본인이 작성한 코드를 자체 채점하는 행위 **금지**. SSOT: [`harness-absolute-rules.md`](harness-absolute-rules.md) "작성 모드 및 리뷰 매트릭스".

## 평가 항목 (7개, 각 10점)

### 1. 정확성 (Correctness)

| 점수 | 기준 |
|:----:|------|
| 9~10 | 엣지 케이스(null, 경계값, overflow) + 동시성 + 장애 시나리오까지 처리 |
| 7~8 | 핵심 로직 정확, 실패 경로(타임아웃, 네트워크 단절 등) 일부 누락 |
| 5~6 | 메인 시나리오만 동작, 예외 시 NPE·상태 전이 오류 가능 |
| 3~4 | 특정 조건에서 명백한 버그, 데이터 정합성 위험 |
| 1~2 | 핵심 기능 미동작 또는 regression |

> **8점 질문:** null이면? 동시 요청이면? 외부 API 5초 무응답이면? → 답이 코드에 있으면 8+

#### 1a. 동시성 필수 체크리스트 (read-decide-write 경로)

**적용 범위**: 스택 독립 원칙. 표의 방어책은 Spring/PostgreSQL 기본 예시 — 타 스택(Python·Node·Go 등)은 동치 기법으로 치환 (락 → advisory lock·Redis Redlock·`sync.Mutex`·DB row lock / atomic update → Redis `INCR`·`UPDATE … WHERE` / 멱등성 키·outbox 는 스택 무관).

아래 패턴 감지 시 **정확성 최대 7점 상한** — 동시성 방지 수단(락·atomic SQL·원자 연산·이벤트 큐) 또는 **명시적 포기 메모**(후술) 중 하나가 코드에 있어야 7점 초과.

| 패턴 | 예시 | 필수 방어 (개념 · (Spring 예)) |
|------|------|-----------|
| 집계 후 상태 전이 | 카운트 ≥ N 이면 플래그 ON, 아니면 OFF | 집계 대상 row 락 또는 단일 SQL UPDATE 에서 집계+판정 (`SELECT … FOR UPDATE` / `UPDATE … WHERE (SELECT COUNT…) >= N`) |
| 중복 방지 insert | "먼저 조회 후 없으면 insert" | UNIQUE 제약 + 충돌 조항 / advisory lock (`ON CONFLICT DO NOTHING`) |
| 잔고/재고 차감 | 읽고 빼고 쓰기 | 원자 UPDATE (`UPDATE … SET x = x - 1 WHERE x >= 1`) |
| 외부 API 호출 + 상태 저장 | 호출 성공 후 DB 저장 | 멱등성 키 · afterCommit 훅 · 트랜잭션 outbox |
| in-memory counter / quota + DB 트랜잭션 | DB 저장 전 `counter++`, 롤백 시 누수 | counter 증가를 DB commit 이후로 이동 (afterCommit) |

> **8점 질문:** 동일 입력이 **2개 쓰레드**에서 동시에 들어와도 최종 상태가 직렬 실행과 같은가? → 답이 코드에 있으면 8+

**명시적 포기 메모 옵션**: 코드 내 방어가 불가능·부적합하고 "일시적 불일치 허용 + 보정 메커니즘(스케줄러·배치·재조회)" 이 설계 의도인 경우에만 7점 상한 해제. **자가 승인 불가** — 다음 3요소 모두 충족해야 한다.

| 요구 요소 | 내용 |
|-----------|------|
| 승인 근거 | 이슈 번호·PRD 섹션·retro 문서 중 하나의 영구 참조 링크 |
| 보정 메커니즘 식별자 | 배치 이름·스케줄러 클래스·재조회 경로 등 코드에 존재하는 식별자 |
| 검증 증거 | 보정 메커니즘이 실제 호출되는 테스트·로그·대시보드 지점 링크 |

`RACE-ACCEPTED: <승인근거> + <보정메커니즘> + <검증증거>` 형식으로 **대상 클래스 JavaDoc 또는 PR 본문**에 기록. 리뷰어는 리뷰 본문에 "확인한 위치(파일·줄·링크)"를 인용해야 7점 초과 부여 가능. 보정 메커니즘 미존재 또는 승인 근거 링크 부재 시 포기 불가.

#### 1b. 프록시 기반 self-invocation 금지 (Spring AOP 예)

**정의**: 본 규칙은 "**프록시/데코레이터/인터셉터 경유 메서드 어드바이스**가 같은 객체 내부 직접 호출(`this.xxx()`)로 인해 적용되지 않는 경우"만 대상으로 한다. 단순 의존성 주입·context 전달·설정 상속은 포함하지 않는다.

**적용 범위**: Spring `@Transactional`·`@Cacheable`·`@CacheEvict`·`@Async` 기본. 타 스택 동치 예:
- Python: `@cached_property` (같은 인스턴스 내부 호출은 해당 없음), **Celery task** — task 를 함수로 직접 호출 시 queue 우회 (`task.delay()` 누락), **FastAPI** 의 `Depends` 는 핸들러에서만 해석 → 내부 함수가 `Depends` 대상 함수를 직접 호출하면 주입 우회
- Node: **Nest** `@UseInterceptors`/`@UseGuards` 는 컨트롤러 진입점에서만 작동 — 서비스 내부 self-call 이면 미적용
- Go: **gRPC interceptor** 는 transport 경계에서만 — 구조체 내부 메서드 self-call 이면 미적용

**N/A 선언**: 해당 스택에 "메서드 경유 프록시 어드바이스" 개념이 없으면 1b 는 N/A — 리뷰 본문에 "1b N/A: <스택 이유>" 1줄 기록 후 skip.

프록시 기반 어드바이스가 붙은 메서드를 **같은 객체 내부에서 `this.xxx()` 로 호출**하면 프록시를 우회해 어드바이스가 적용되지 않는다. **피호출자에 어드바이스가 있으면 호출자 어노테이션 유무와 무관하게 적중** — 정확성 **최대 6점 상한** (통과 조건 최저 ≥7 자동 미달). 리뷰어 재량 완화 불가.

| 안티 패턴 | 올바른 패턴 |
|-----------|------------|
| `evaluateAll()` 내부에서 `this.evaluate(id)` 호출 (evaluate 에 `@Transactional`) | 호출자(스케줄러·컨트롤러) 에서 주입된 프록시 빈 경유 직접 호출 |
| 같은 클래스의 `@Cacheable` 메서드를 내부 helper 에서 호출 | 별도 빈으로 분리 |
| `@Async` 메서드를 같은 빈에서 self-call | 호출 분기를 다른 빈으로 이동 |

`AopContext.currentProxy()` 는 지양 — 테스트 이중성(프록시 의존 테스트)·AOP 컨텍스트 누수·Spring 공식 문서 비권장. 부득이 사용 시 PR 본문에 근거 명시 요구.

**인접 프록시 미적용 패턴 주의** (self-invocation 외 리뷰어 자주 누락):
- **private/final 메서드에 어드바이스** — CGLIB 프록시가 override 불가, 어드바이스 미적용. `public` + non-final 로 전환 필요
- **`@PostConstruct` / 생성자 내부에서 어드바이스 메서드 호출** — 프록시 생성 **전** 호출이므로 어드바이스 미적용
- **`@Configuration` 클래스 내 `@Bean` 메서드 self-call** — `@Bean` 의 싱글턴 보장은 프록시 경유 — proxyBeanMethods=false 면 깨짐

> **8점 질문:** 같은 빈 내 `this.xxx()` 로 **어드바이스가 붙은** 메서드를 호출하는 곳이 있는가? (호출자에 어드바이스 여부 무관, **피호출자 기준**) → 있으면 정확성 ≤6

### 5. 보안 (Security)

| 점수 | 기준 |
|:----:|------|
| 9~10 | 입력 전부 검증, Injection·XSS·CSRF 방어, 인증/인가 정확, 민감정보 설정 분리, 로깅에 개인정보 미노출 |
| 7~8 | 주요 보안 처리됨, 입력 길이 미제한·스택트레이스 노출 등 방어적 검증 일부 누락 |
| 5~6 | 인증은 있으나 인가 누락 엔드포인트 존재, 입력이 검증 없이 쿼리에 결합 |
| 3~4 | 하드코딩 API 키, 패스워드 평문 저장, 인증 우회 가능 |
| 1~2 | 인증 없이 관리자 기능 접근 가능 |

#### 5a. 파라미터 위변조 방지 (BOLA/IDOR)

**원칙**: 신원·권한·등급·금액 등 **결과를 좌우하는 값은 신뢰 경계 안쪽에서 결정**한다. 경계 바깥이 보내는 파라미터는 "무엇을 요청하는지" 만 전달하고 "그럴 자격이 있는지" 는 전달하지 않는다.

**적용 절차** (상세 SSOT → [`harness-trust-boundary.md`](harness-trust-boundary.md)):

| 단계 | 내용 |
|:----:|------|
| 1 | 대상 **엔드포인트**의 노출 등급 확정 — **E**(외부 공개) / **I**(내부 전용) / **A**(운영자 전용). **미선언 시 E** |
| 2 | I·A 는 `TRUST-BOUNDARY` 증거 필수. 결손·원문 열람 불가 → **fail-closed, E 재판정** |
| 3 | 등급별 **판정표 전행 대조** → 적중 행의 **보안 상한** 적용 |

**보안 상한**: 적중 행의 `보안 상한` 열 값(**3 또는 6**)을 그대로 적용한다. 상한 6 이하는 통과 조건(최저 ≥7) 자동 미달. 행 목록·등급별 적용·상한값은 SSOT 단독 보유.

> **8점 질문:** 신뢰 경계 바깥에서 모든 파라미터를 임의 값으로 바꿔 보내도 타인 리소스 접근·권한 상승·금액 조작이 불가능한가? (I 등급은 lateral movement 기준 — [`harness-trust-boundary.md`](harness-trust-boundary.md) §4)

**N/A**: 인증 불요 공개 리소스, 또는 요청 주체·권한 개념 자체가 없는 변경 — 리뷰 본문에 "5a N/A: <이유>" 1줄 기록 후 skip.

### 6. 성능 및 효율성 (Performance)

| 점수 | 기준 |
|:----:|------|
| 9~10 | 복잡도 최적, N+1 없음, 적절한 캐싱, 대용량 시 스트리밍/배치/페이지네이션 |
| 7~8 | 현재 규모 문제없음, 10배 증가 시 병목 1~2개 잠재 |
| 5~6 | 루프 안 DB 호출(N+1), 전체 테이블 스캔, 무한 증가 컬렉션 메모리 유지 |
| 3~4 | O(n²)이 핫 패스에 존재, 커넥션/리소스 누수 가능 |
| 1~2 | 프로덕션 배포 시 즉시 장애 |

> **8점 질문:** 데이터 100배 증가 시 버티는가? 또는 페이지네이션/캐싱으로 대응 가능한가?

### 7. 유지보수성 및 컨벤션 (Maintainability)

| 점수 | 기준 |
|:----:|------|
| 9~10 | 컨벤션 100% 준수, 커밋 의미 단위 분리, 설정 외부화, 로깅 적절, 기존 패턴과 일관 |
| 7~8 | 컨벤션 대부분 준수, 커밋 약간 뭉뚱그려짐, 로깅 일부 과부족 |
| 5~6 | 스타일 혼재, PR에 관련 없는 변경 혼입, 커밋 메시지 "fix" 수준 |
| 3~4 | 기존과 다른 패턴 독자 도입, 불필요한 라이브러리, 설정값 하드코딩 |
| 1~2 | 린트 에러 무시, 빌드 경고 방치, 주석 처리 코드 대량 방치 |

> **8점 질문:** 처음 보는 동료가 기존 코드와 구분 못 할 정도로 일관되는가?

## 판정

[9]는 **2축 병렬**이다 — `[9-코드]`(본 문서) ∥ `[9-인프라]`([`harness-infra-review.md`](harness-infra-review.md)). 통과는 두 축 AND 결합이며, 중복 지적·상반 판정 조정은 인프라 문서의 "관할 경계" 절이 SSOT.

**통과 조건 (모두 충족):**

| 조건 | 기준 |
|------|------|
| 평균 | ≥ 8.0 |
| 각 항목 최저 | ≥ 7 |
| 인프라 축 | BLOCK 0건 + 미해결 ASK 0건 |

최저 미달 시 평균 8.0 이상이어도 **미통과**. 아래 특수 규칙의 **점수 상한은 리뷰어 재량으로 완화 불가** — 상한이 6 이하면 해당 항목이 최저 기준(≥7)에 자동 미달한다. 재시도 카운트 소비 단위는 SSOT [`harness-absolute-rules.md`](harness-absolute-rules.md) "재시도 한도" 를 따른다 (사이클 단위, 조건부 재검증 미소비).

**합성 규칙 (필수):**

| 상황 | 처리 |
|------|------|
| 동일 항목에 **상한이 복수 적중** (예: 1a 7 + 1b 6) | **가장 낮은 상한을 채택** |
| 동일 항목에 **상한 + 감점 동시 적용** (예: 1a 7 + Think 위반 -1) | **감점을 먼저 적용한 뒤 상한으로 클램프** — `min(원점수 - 감점, 상한)` |

**특수 규칙 (1a · 1b · 5a · Coding Principles):** 상한형·감점형은 점수로 표현하며 **별도 FAIL 경로 없음**. 선행 판정은 적용 범위 게이트이며 그 자체로 점수를 만들지 않는다.

| 서브섹션 | 유형 | 대상 항목 | 효과 |
|----------|------|-----------|------|
| 1a 동시성 체크리스트 | 상한형 | 1 정확성 | 방어책 + 명시적 포기 메모 모두 없음 → **최대 7점** (통과 경계, 미달 아님) |
| 1b self-invocation 금지 | 상한형 | 1 정확성 | 피호출자 어드바이스 보유 + 같은 빈 `this.xxx()` 호출 1건 이상 → **최대 6점** |
| 5a 파라미터 위변조 | 상한형 | 5 보안 | 판정표 적중 시 **최대 3점 또는 6점** — 행·등급별 상세는 [`harness-trust-boundary.md`](harness-trust-boundary.md) §3 |
| 5a 노출 등급 선언 | 선행 판정 | — | 미선언 → **E 기본값**. I·A 증거 결손·열람 불가 시 선언 무효 → **E 기준 재판정** (점수 아님) |
| Coding Principles 위반 | 감점형 | 1 · 2 · 7 | Think 위반 → 1 정확성 -1, Simplicity 위반 → 2 설계 -1, Surgical 위반 → 7 유지보수성 -1 (CLAUDE.md `## Coding Principles` 참조) |

**재시도:** 미통과 → Dev Agent 재투입 (**최대 5회** — [9] 단계 한정, **코드+인프라 공통 카운터, 사이클 단위 소비**). **5회 미달 시 자동 중단 + 사용자 결정 요청** (강행/재설계/중단). 임계 완화 금지 — SSOT: [`harness-absolute-rules.md`](harness-absolute-rules.md) "재시도 한도".

> **5회는 잠정값** (관측 데이터 없이 채택). **4회 이상 소진 사례 3건 누적 시 적정성 재검토** — 소진 발생 시 회고[12] 또는 해당 PR 에서 회차·사유를 `docs/research/` 에 1줄 기록. 기록 없이 추가 완화 금지.

**이슈 처리:** High/Mid → Dev Agent 자동 수정. Low → 테이블 제시, 사용자 선택.
