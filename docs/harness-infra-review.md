# Harness: 인프라 리뷰 기준

[9] 단계에서 **코드 리뷰와 병렬로 실행**되는 인프라 관점 리뷰의 기준 SSOT. 코드 리뷰 기준은 [`harness-code-review.md`](harness-code-review.md).

## ⛔ 실행 주체 · 접근 제약

- **반드시 메인 런타임의 서브에이전트**가 수행 (Claude-Lead=Agent 툴 / Codex-Lead=`spawn_agent`). 메인 셀프 채점 금지. SSOT: [`harness-absolute-rules.md`](harness-absolute-rules.md) "작성 모드 및 리뷰 매트릭스"
- **⛔ 실인프라 접근 전면 금지**: 본 리뷰는 **정적 분석 전용**이다. DB·Redis·k8s·메시지 브로커 조회·접속, MCP DB 도구 사용, `kubectl`·`redis-cli`·`mysql` 등 실행 금지. 위반 감지 시 **결과 폐기 + 재발사**(재시도 카운트 미소비). **재발사 상한 2회** — 3회째 위반 시 중단 + 사용자 보고 (무한 재발사·토큰 소진 차단)
- 리뷰 결과 파일 생성 금지. 판정은 응답 텍스트로만 반환

## 성격 (2단계 게이트)

인덱스 존재·파티션·토픽 설정은 코드만으로 확인 불가하다. 따라서 본 리뷰는 **자문이 1차 목적**이며, 차단은 diff 만으로 확정 가능한 결함에 한정한다.

| 등급 | 의미 | 절차 영향 |
|------|------|----------|
| **BLOCK** | diff 만으로 확정 가능한 결함 | [9] 미통과 — Dev Agent 수정 후 재실행 |
| **ASK** | 중단 후 사용자 결정 필요 | 진행 중단 + 사용자 결정(강행/수정/분할) |
| **WARN** | 자문 | **절차 무영향** — PR 본문 노트로만 전달 |

## 발사 조건

| 대상 | 처리 |
|------|------|
| 코드 프로젝트 | **항상 발사** |
| 5영역 전부 무해당 | `인프라 리뷰 N/A: 해당 변경 없음` 1줄 반환 후 즉시 종료 (저비용 경로) |
| 콘텐츠 프로젝트 · 하네스 메타 변경 | 발사 skip — `rp-ship` 이수 확인에서 **정당한 skip = 이수**로 간주 |
| Lite 트랙 | **필수 유지** (QA·코드리뷰와 동일). 무해당 시 N/A 1줄 |

**우선순위**: 조건이 겹치면 **skip 이 우선**한다 (예: 하네스 메타 변경 ∩ Lite 핫픽스 → 발사 skip). Lite 의 "필수 유지"는 코드 프로젝트 전제다.

## 스택 독립 원칙

기본 예시는 Kotlin/JVM · MySQL/StarRocks. 타 스택은 **동치 기법으로 치환**한다 (기존 [`harness-code-review.md`](harness-code-review.md) 1a·1b 와 동일 원칙).

| 기본 예시 | 동치 치환 |
|-----------|----------|
| 중첩 `runBlocking` | 중첩 `asyncio.run` / async 함수 내 동기 blocking IO / 루프 내 `await` 직렬 호출 |
| MySQL·StarRocks | PostgreSQL·ClickHouse·BigQuery 등 대상 엔진의 방언·타입 체계 |
| Redis · Kafka | 동등 캐시·메시지 브로커 (Memcached·Valkey / RabbitMQ·SQS·Pub/Sub) |

해당 스택에 개념이 없으면 `N/A: <스택 이유>` 1줄 기록 후 skip.

## 검사 5영역

### 1. SQL 품질 (전부 WARN)

| 축 | 검사 |
|------|------|
| 방언 정합 | 대상 엔진 미지원 문법·함수·예약어, 엔진별 데이터 로드 방식 적합성 |
| 실행계획 추정 | WHERE·JOIN 컬럼 기준 **인덱스 활용 가능성**, 풀스캔, 깊은 OFFSET 페이징, 불필요 `SELECT *`, 정렬·그룹 비용. **인덱스 존재 여부는 미확인 전제** — "인덱스가 없다" 같은 확정 표현 금지, "해당 인덱스가 없으면 풀스캔" 형태로 서술 |
| 타입·정밀도 | 금액·율·수량에 `double`·`float` 사용 → `decimal(p,s)` 권고. 자릿수·스케일 부족으로 인한 절사·반올림, 암묵 형변환으로 인한 인덱스 무효화, 문자셋·콜레이션 불일치 |
| 쓰기 패턴 | 대량 insert 배치 **500~2000건** 권고. 배치 간 슬립은 **복제 지연·부하 지표 기반 조절**이 원칙이며, 관측치가 없을 때의 보수적 기본값이 **1초**. 트랜잭션 범위·장기 락, 무제한 UPDATE·DELETE, DDL 시 테이블 락·다운타임 |

### 2. Redis

| 패턴 | 등급 |
|------|------|
| 전체 키 순회 | **BLOCK** (B2) |
| 단일 키 값 1MB 초과 추정 | WARN |
| 단일 키 값 2MB 초과 | **ASK** (근거 인용 시에만) |
| 상한 없는 컬렉션 캐싱, TTL 부재 | WARN |

### 3. 비동기 · 스레드 점유

| 패턴 | 등급 |
|------|------|
| 중첩 `runBlocking`, 루프·스트림 본문 내 `runBlocking` | **BLOCK** (B1) |
| 단일 `runBlocking`, `GlobalScope`, Default 디스패처에서 blocking IO, 타임아웃 없는 외부 API 호출 | WARN + 대안 제시 |

### 4. 직렬화 호환

| 변경 | 등급 |
|------|------|
| 필드 삭제·타입 변경·이름 변경·enum 값 제거·FQCN 이동 | **BLOCK** (B3) |
| nullable 필드 추가, 기본값 있는 변경 | WARN |

### 5. 배포 전략 · pub/sub (전부 WARN)

매니페스트·CI 로 배포 전략을 판별한다. 판별 불가 시 **"전략 미판별 — 롤링 가정"** 을 리포트에 명시한다.

| 전략 | 관점 |
|------|------|
| 블루그린 | 전환 시점 일괄 교체 — 구·신 동시 존재 구간이 짧음. 위험도 낮음 |
| 카나리·롤링 | **구·신 동시 존재 전제** — 스키마 변경, 캐시 포맷 변경, 메시지 계약 변경, 구독 변경(토픽·컨슈머그룹·파티션 수)이 부분 트래픽 장애를 유발할 수 있음 |

리포트에 **선행 인프라 작업 목록**(토픽 생성·파티션 증설·인덱스 추가·리소스 증설 등)을 분리 제시한다.

## BLOCK · ASK 부여 조건

**정적 확정 가능해야 부여한다.**

| 등급 | 부여 조건 (전부 충족) | 제외 — WARN 처리 |
|------|---------------------|-----------------|
| **B1** 중첩·루프 `runBlocking` | 동일 함수 본문 내 직접 중첩, 또는 반복문·스트림 본문 내 `runBlocking` 호출이 diff 에 보임 | 호출 경로상 **간접** 중첩(콜그래프 미확정) / 테스트 코드·`main()`·일회성 CLI·배치 스크립트의 관용 사용 |
| **B2** Redis 전체 키 순회 | `KEYS`·`keys('*')` 호출, 또는 커서 종료 조건·배치 상한이 **없는** SCAN 루프 | 종료 조건 + `COUNT` 상한이 있는 정상 커서 페이지네이션 / 테스트 픽스처·로컬 운영 도구 |
| **B3** 파괴적 직렬화 변경 | (i) 대상 타입이 캐시 저장 또는 메시지 페이로드로 쓰임을 **diff 또는 diff 가 참조하는 직접 호출부**에서 확인(전역 탐색 불요) + (ii) 필드 삭제·타입 변경·이름 변경·enum 값 제거·FQCN 이동 중 1건 | 신규 도입 타입(구버전 소비자 부재) / 마이그레이션·스키마 버전 필드 동반 변경 / **(i) 확정 불가 시 WARN 강등** |
| **ASK** Redis 값 2MB 초과 | (i) 크기 상한이 코드에 없음 + (ii) 건수·요소당 크기 근거를 코드·스키마에서 **인용 가능** | 근거 인용 불가 시 WARN 강등 |

### 인용 의무 · 해제 경로 (BLOCK · ASK 대칭 적용)

| # | 규칙 |
|:-:|------|
| 1 | 부여 시 **파일·줄 인용 의무**. 인용 불가 → 한 등급 강등 (BLOCK→WARN, ASK→WARN) |
| 2 | Dev Agent 가 정적 근거로 반박 시 → BLOCK 은 **ASK 로**, ASK 는 **사용자 결정으로** 이관. **사이클당 1회, 재반박 금지** |
| 3 | **최종 심사 주체는 사용자.** 반박은 판정 번복이 아니라 **결정 이관**이므로 메인 셀프 채점 금지 조항과 충돌하지 않는다 |
| 4 | ASK 사용자 결정(강행/수정/분할)과 근거는 PR 본문 노트에 1줄 기록. **강행 시 같은 사이클 내 재제기 금지** |

**"미해결 ASK" 정의**: 사용자 결정이 내려지지 않은 ASK. **강행·수정·분할 중 어느 결정이든 내려지면 해결로 간주**한다 (강행 선택도 해결). 통과 조건의 `미해결 ASK 0건`은 이 정의를 따른다.

## 지적 후처리 (자동 수정 범위)

| 구분 | 처리 |
|------|------|
| BLOCK + **코드 등가 치환** WARN (`decimal` 전환, `SELECT *` 컬럼 명시, 깊은 OFFSET → 커서 페이징, 암묵 형변환 제거, 타임아웃 부여) | 1차 리뷰 종료 후 Dev Agent 자동 수정 |
| **런타임 동작·소요 시간을 바꾸는** WARN (배치 크기, **슬립 삽입**, TTL, 캐시 분할) | **자동 수정 금지** — 권고값·근거만 제시. 근거 없는 지연 자동 주입으로 성능을 회귀시키지 않기 위함 |
| 인프라 의존 WARN (인덱스·파티셔닝·토픽 설정·리소스 증설) | 자동 수정 금지. PR 본문 "인프라 선행 작업"으로 분리 |
| ASK | 진행 중단 + 사용자 결정 |

## 관할 경계 (SSOT — 타 문서는 본 절 링크 참조)

| 상황 | 처리 |
|------|------|
| 동일 결함이 코드 항목 6(성능)과 인프라 1영역에 모두 해당 (N+1·풀스캔·무제한 컬렉션) | **코드 리뷰 감점 우선**, 인프라는 중복 감점 없이 개선 방법만 WARN |
| 인프라 1영역과 [5] 엔지 리뷰([`harness-db.md`](harness-db.md) 참고) 중복 | [5]는 설계 시점 스키마·모델, [9-인프라]는 구현된 쿼리·DDL 대상. 동일 지적 반복 시 [9]는 링크만 |
| 코드 5a 안티패턴 4(대량 처리 범위 미통제)와 인프라 1영역 쓰기 패턴(무제한 UPDATE·DELETE) 중복 | **코드 축 상한 우선**, 인프라는 중복 지적 없이 개선 방법만 WARN |
| 인가 설정(mTLS·메시 정책·ingress 라우트) 판정 | **코드 축 5a 관할**. 인프라 축은 배포 전략 관점만 보며 **인가 판정 금지**. 코드 축은 증거를 인용할 뿐 실효성 판단을 대행하지 않고, 열람 불가 시 fail-closed |
| 두 축 상반 판정 | 더 보수적인 쪽 채택 (BLOCK > ASK > WARN > 무지적). 코드 점수와 인프라 등급은 **독립 판정** — 서로의 점수를 조정하지 않는다 |

## 임계값 · 등급 승격

| 항목 | 규칙 |
|------|------|
| 임계값 오버라이드 | 본 문서 수치는 **잠정 기본 권고값**. 프로젝트 `CLAUDE.md` 의 `## 인프라 리뷰 임계값` 섹션에서 **수치 4종(1MB · 2MB · 배치 건수 · 슬립)만** 오버라이드 가능. **BLOCK 부여 조건·등급 체계 오버라이드 금지** |
| WARN → BLOCK 승격 | (i) 정탐 3건 이상 + 오탐 0건 근거 (ii) 정적 확정 조건표 작성 (iii) 하네스 메타 변경 PRD 경유 — **3요건 모두 충족 시에만**. 임의 승격 금지 |
