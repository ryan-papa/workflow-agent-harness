# PRD: 5a 파라미터 위변조 방지 — 노출 등급(E/I/A) 선행 판정

**상태:** In Review
**유형:** 하네스 메타 변경 (간소 PRD)

---

## 변경 이유

1. **과잉 차단 해소** — PR #67·#68 로 도입한 코드리뷰 5a 는 신뢰 경계를 "클라이언트 = 불신" 으로 고정했다. mTLS·서비스 메시 사이드카로 전송 계층에서 호출자 인가가 확립된 내부 API 도 보안 최대 3점 상한에 걸려, 주체 결정을 호출측 서비스가 맡는 정상 설계가 미통과 처리된다. 기존 N/A 경로는 "인증 불요 공개 리소스" 만 덮어 이 케이스에 적용 불가 — 내부 API 는 인증이 없는 게 아니라 **인증이 다른 계층에 있다**.
2. **판정 합성 규칙 부재** — PR #68 의 FAIL형 → 상한형 전환 과정에서 동일 항목 복수 상한 적중·상한 × 감점 중첩의 처리 규칙이 정의되지 않아, 구 규칙에서는 불가능했던 통과 역전 경로가 생겼다 (1a 7 + 1b 6 동시 적중 시 최대값 채택하면 통과).
3. **문서 분량 규칙 현실화** — 기본 300줄 / 최대 500줄 2단 기준이 실제 운영에서 경고만 누적시켰다. 500줄 단일 기준으로 통일한다.

### 분량 기준 변경을 동일 PR 에 포함한 근거

500줄 단일 기준은 5a 와 직교한 별개 결정이며 사용자 지시로 확정됐다. 본 PR 이 `harness-code-review.md` 를 키운 것과 인과 관계가 없다 — 기준 변경 없이도 해당 파일은 hard limit 500 이내였고, 변경된 것은 **경고 임계(300)** 뿐이다. 분리 PR 로 뺄 경우 같은 파일을 두 PR 이 건드려 충돌 비용만 발생한다.

### 5a 문서 분리 근거 (사이클 4 재설계)

코드 축이 사이클 1~3 에서 평균 6.4 → 6.7 → 6.9 로 오르면서도 8.0 을 넘지 못했고, 미달 사유가 **규칙의 위험성이 아니라 표 간 정합성**으로 고정됐다. 같은 판정(어느 적중 조건이 어느 등급에 적용되고 상한이 얼마인가)이 **안티패턴 표·판정표·증거표·산문 4곳에 중복 표현**돼 한쪽만 고치는 드리프트가 세 사이클 연속 재발했다.

**회차 정의**: 리뷰 발사 1회 = 1사이클. **발사 5회 = 사이클 5, 한도 전량 소비**(잔여 0회). SSOT [`harness-absolute-rules.md`](../../harness-absolute-rules.md) 의 비소비 사유는 ASK 발생·실인프라 접근 위반 폐기 2종뿐이므로, 그 밖의 사유로 회차를 감하지 않는다.

분량 문제가 아니다 — 500줄 기준으로 여유가 있었다. **중복 표현 구조 자체를 제거**하는 것이 해법이므로, 5a 를 SSOT 문서로 분리하면서 안티패턴 표와 판정표를 **단일 판정표**로 병합했다. 표 **본문**의 드리프트는 이로써 제거됐다. 다만 표를 **가리키는 문구**(행 개수·행 열거)가 메타데이터 층에서 같은 드리프트를 재생산했고, 그 대응은 사이클 4 반영 절 참조.

문서 전용 변경이며 런타임 영향 없음. `git revert` 로 단일 커밋 되돌리기 가능하다.

| 노출 등급 도입 | 5a 가 PR #68 상태(전면 적용)로 복귀 — 내부 API 과잉 차단 재발 |

등급 완화가 과하다고 판단되면 전체 revert 대신 **I 등급 해제 범위만 축소**(판정행 2·3 을 적용으로 환원)하는 경로를 우선한다.

### 사이클 4 지적 반영 (사이클 5 커밋)

분리·단일화가 판정 매트릭스의 드리프트는 제거했으나, **개수 라벨·행 열거라는 메타데이터 중복**을 새로 만들었다. "한 행 = 한 판정이므로 드리프트가 구조적으로 불가능" 이라는 직전 주장은 이 점에서 성립하지 않았다 — 표 본문이 아니라 표를 **가리키는 문구**가 5개 파일에 복제돼 있었다.
