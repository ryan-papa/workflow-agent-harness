## 결정 사항

| # | 항목 | 결정 | 기각 대안 | 근거 유형 |
|:-:|------|------|-----------|-----------|
| 1 | 반영 검증 규칙 | SSOT "리뷰 단계 = 관점 분리" 에 **"리뷰 지적 반영 검증"** 문단. ① **반영 전 확인**: 수정안이 기존 오류 처리·출력 형식 / PRD 결정 표·이전 단계 리뷰 반영분 / 상대 축 영역과 충돌하는지. ② **충돌 시**: 수정안을 조정해 충돌 없이 반영. 불가하면 이전 결정 번복으로 보고 PRD 결정 표 갱신 후 ③ 재검증. 판단 불가면 사용자 결정. ③ **재검증 트리거**: 리뷰 통과 후 동작·출력·분기·결정이 바뀌는 수정(리네이밍·문구·주석 제외), 적용 범위 [4]~[11] (rp-pr-review 반영 포함). **대상 축** = 변경 관점의 통과 축 + 번복된 결정을 판정한 축(이전 단계 [4]·[5] 포함, 새 서브에이전트, 프롬프트에 이전 결정·변경 사유). 카운트 미소비·같은 사이클 연쇄 금지는 기존 조건부 재검증과 동일, **이전 단계 축 재검증 미달 시 수정 철회 또는 사용자 결정** (재검증 2회차 양 축 제안 채택). rp-pr-review 지적은 후속 사이클 반영 시 적용. ④ **흔적**: 재리뷰·재검증 프롬프트 수정 내역에 `충돌 확인: 없음` 또는 `충돌 확인: <대상 결정>` 1줄(괄호 부연 허용), 세션 transcript 가 집계 근거. 확인은 채점이 아니므로 셀프 리뷰 금지와 무충돌 | `harness-code-review.md` 단독 기재 — [4]·[5] 미적용 · 신규 체크리스트 파일 | 사용자 결정 (SSOT 위치·세부는 엔지니어 선호) |
| 1-1 | 스킬 동기화 | `rp-plan-review`·`rp-eng-review`·`rp-code-review`·`rp-infra-review` 조건부 재검증 줄에 SSOT "리뷰 지적 반영 검증" 링크 1구 + `.codex` 동기화 (축별 트리거 문구는 유지) | SSOT 링크만 (스킬 미갱신) — 미준수 재발 경로 | 엔지니어 선호 |
| 2 | 실패 형식 통일 | `토큰: 집계 누락` → `토큰: 집계 실패 — 라벨 불일치`. 스크립트 출력이 아니라 **메인이 직접 출력**하는 사유 코드임을 문장에 명시 | 별도 형식 유지 | 엔지니어 선호 |
| 3 | transcript 형식 | `session_meta` cwd 가 문자열이 아니면 후보 제외. 같은 결함 계열 일괄 차단([9] Info 반영): `read_jsonl` 은 dict 행만 반환, 중첩 필드(`message`·`content` 항목·`input`·`usage`·`payload`·`info`·`arguments`)는 `obj()` 로 `{}` degrade, `timestamp` 는 `str()` 비교 — Fail 경로 유지, 트레이스백 0 | 예외 catch 후 Fail | 엔지니어 선호 |
| 4 | 조기 종료 테스트 | poison 크래시 대신 모듈 전역 `read_jsonl` 을 호출 기록(spy)으로 교체해 오래된 파일 미파싱 검증, `try/finally` 원복 + 비문자열 cwd·비 dict 행 픽스처는 정상 skip 검증 | 권한 0 파일 — OS 의존 | 엔지니어 선호 |
