## 결정 사항

| # | 항목 | 결정 | 기각 대안 | 근거 유형 |
|:-:|------|------|-----------|-----------|
| 1 | 자동 선택 임계값 | 1위 ≥ **9.0** + 단독 1위 | 9.5 유지 — 질문 과다 | 창업자 직감 (사용자 지시) |
| 2 | 요청 상충 판정 | **채점 전 대조 단계**: 각 선택지를 사용자 발화·확정 답변·PRD 확정 결정과 대조. 일부 상충·판단 불확실도 상충으로 간주 | 사용자 발화만 — 이전 확정 결정 번복 누락 · 판정 절차 없이 "상충이면 감점"만 — 원 실패(채점자 미인지) 재발 | 제품 가설 |
| 3 | 감점 폭 | **-0.5** (0.5 단위 최소폭, "아주 조금") | -1.0 이상 — 사용자 요청 "아주 조금" 과 불일치 | 창업자 직감 (사용자 지시) |
| 4 | 자동 선택 제외 | 요청 상충 선택지는 감점 후에도 최고점이면 **질문으로 제시**, 자동 선택 금지 | 감점만 적용 — 9.5→9.0 이 새 임계값 통과해 문제 재발 | 엔지니어 선호 |

| 6 | 사용자 번복 기록 | 사용자가 상충 선택지를 고르면 사용자 결정 — PRD `사용자 결정(요청 번복):` 접두 | 기록 없음 — 이전 결정과 충돌 추적 불가 | 엔지니어 선호 |
| 7 | SSOT | 수치(9.0·-0.5)는 `CLAUDE.md` 단독, AGENTS·rp-specify 는 참조만 | 3곳 수치 반복 — 다음 변경 시 누락 | 엔지니어 선호 |
| 8 | 질문 예시 | 예시 1위 9.0 → 8.5 (새 규칙상 9.0 단독은 자동 선택) + 4번에 `⚠ 요청 상충` 표기 예시 | 유지 — 규칙과 모순 | 엔지니어 선호 |
