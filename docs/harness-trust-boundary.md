# Harness: 신뢰 경계 판정 (코드 리뷰 5a SSOT)

코드 리뷰 보안 항목 **5a 파라미터 위변조 방지(BOLA/IDOR)** 의 단일 기준 문서. 점수 체계·통과 조건은 [`harness-code-review.md`](harness-code-review.md) 가 SSOT 이며, 본 문서는 **무엇이 적중이고 상한이 얼마인가** 를 정의한다.

## 원칙

신원·권한·등급·금액 등 **결과를 좌우하는 값은 신뢰 경계 안쪽에서 결정**한다. 경계 바깥이 보내는 파라미터는 "무엇을 요청하는지" 만 전달하고 "그럴 자격이 있는지" 는 전달하지 않는다.

**인증 컨텍스트** = 세션·JWT 클레임·서버 세션 스토어 등 **호출자가 변조 불가능한 출처**. 스택 독립.

## 1. 노출 등급 (선행 판정)

5a 적용 전 대상 **엔드포인트(핸들러 메서드)** 의 등급을 확정한다.

| 등급 | 정의 | 경계 바깥 |
|:----:|------|-----------|
| **E** External | 외부 공개 — 대고객 앱·웹·퍼블릭 API | 최종 사용자·외부 조직 |
| **I** Internal | 내부 전용. 외부 미노출 + **호출자 인가 확립(계층 무관)**. 주체 결정은 호출측 서비스 책임 | 동일 신뢰 도메인의 다른 워크로드 |
| **A** Admin | 인증된 운영자 전용 | 인증된 운영자 |

**미선언 시 기본값 = E** (보수적 판정).

| 중간 형태 | 확정 등급 |
|-----------|-----------|
| 모바일 앱 전용 · 파트너 전용 API | **E** — 경계 바깥에 최종 사용자·외부 조직이 있으면 호출자 인가 확립 여부와 무관 |
| 인터넷 노출 admin 콘솔 | **E** 확정 + A 의 역할 검사 요건 **중첩 적용** |
| 한 컨트롤러에 노출 면이 다른 핸들러 혼재 | 클래스 단위 금지 — **엔드포인트 단위 개별 판정** |

**선언 단위 = 엔드포인트.** 클래스 주석·PR 본문·프로젝트 문서 **어디에 기록하든 적용 대상 엔드포인트를 명시 열거**한다. 열거 없는 일괄 선언은 무효. 경로 접두어·와일드카드 서술(`/internal/**` 등)은 리뷰어가 **라우트 정의에서 대상 엔드포인트의 포함을 확인**한 경우에만 유효하다.

## 2. 증거 (I·A — 자가 선언 불가)

증거는 **이름**으로 식별한다 (선언 형식의 플레이스홀더와 동일). 번호를 쓰지 않는 이유는 등급마다 요소 구성이 달라 같은 번호가 다른 대상을 가리키기 때문이다.

| 등급 | 증거 | 입증할 사실 | 확인 형태 |
|:----:|------|-------------|-----------|
| **I** | `격리` | 해당 엔드포인트가 **외부에서 도달 불가** | 설정 원문 **또는 문서 서술** |
| **I** | `인가` | **허용 호출자가 열거**되고 그 밖은 기본 거부 | 설정 원문 **또는 문서 서술** |
| **I** | `계약` | 주체 결정 책임이 **호출측**에 있음 | 기록 위치 |
| **I** 조건부 | `호출측검증` | **호출측 소유권 검증 지점** — 판정행 2·4b 를 해제할 때만 요구 | 검증 코드 **원문 발췌** (문서 서술 불인정) |
| **A** | `인증설정` | 해당 경로를 덮는 인증 설정 | 파일·줄 **또는 문서 서술** |
| **A** | `역할검사` | 역할·스코프 검사 코드 | 파일·줄 |
| **I·A** | `환경범위` | 선언이 유효한 환경 | 원문 근거: **`격리`·`인가`(A 는 `인증설정`) 원문 내에서 식별 가능한** 환경 식별자 — 파일 경로·네임스페이스·프로파일 키 등 / 문서 근거: 문서가 **환경별 노출 면을 구분 서술**하거나 **적용 환경을 명시 열거**("운영·스테이징 동일" 등 전 환경 동일 표기 포함). **문서 근거에 한해** — 환경 언급이 전혀 없으면 **프로덕션 한정 선언**으로 좁혀 읽고 그 밖 환경은 **미선언**(E). 침묵을 전 환경 충족으로 읽지 않는다 |

**수단은 스택 자유** — 서비스 메시 정책·API 게이트웨이 허용목록·사설 서브넷·방화벽 규칙 무엇이든 무방하다. 판정 기준은 "무엇을 썼는가" 가 아니라 **위 사실이 리뷰어가 읽을 수 있는 근거로 확인되는가** 이다.

### 근거 유형 2종

| 유형 | 충족 수단 | 적중 행 상한 | 리뷰 본문 의무 |
|------|-----------|:------------:|----------------|
| `원문 근거` | 확인 형태에 **"문서 서술" 대안이 있는 요소 전부**(`격리`·`인가`·`인증설정`·`환경범위`)가 설정·코드 원문(파일·줄)으로 확인 | 판정표 값 그대로 | 확인한 파일·줄·설정 경로 인용 |
| `문서 근거` | **요소 하나라도 문서 서술로 충족**(= `원문 근거` 의 여집합 전부) | **-1 하향** (§3 각주, 보고용) | 위 + `문서 근거 완화: <파일·섹션> "<인용 문장>"` 1줄 |

**문서 서술** = 리뷰 대상 레포에 **머지된 문서 파일**(`README.md`·`docs/` 등. 코드 주석·PR 본문은 문서 서술이 아니다)에서 해당 엔드포인트의 **노출 면·허용 호출자 범위**를 서술한 산문·표. 표기 대응: **내부 전용 = I · 대고객 = E · 운영자 = A**. **자유 형식** — 전용 섹션·고정 서식 불요. 별도 `TRUST-BOUNDARY` 선언이 없어도 **서술 자체를 선언으로 인정**하되 §1 선언 단위 규칙은 그대로 적용된다 — 서술에서 **적용 엔드포인트가 식별 가능**해야 하며, 식별 불가한 일괄 서술은 무효다.

#### 문서 근거 요건 (전부 충족 — 하나라도 미충족 시 E 재판정)

| 요건 | 내용 |
|------|------|
| **기준선** | **머지된 기준선**(리뷰 대상 diff 밖) 서술만 인정. 같은 PR 의 **신규 추가·수정 서술은 자가 선언**이므로 **문서 근거 불가** — 그 PR 은 `원문 근거`로만 판정한다 |
| **라우트 무변경** | 같은 PR 이 그 엔드포인트의 라우트·노출·인가 설정을 **신규 추가·변경**하면 원문 근거만 허용. **라우트 = 핸들러 매핑 선언 + 게이트웨이·ingress 등록 모두** → **신규 엔드포인트는 문서 근거 불가** |
| **선행 금지** | 서술이 **구현보다 선행**하면(서술 시점에 그 엔드포인트가 레포에 부재) 기준선이 아니라 **예고** → 불인정. **선후 판정 불가 시 결손** |
| **선행 금지 — 예외** | 와일드카드 서술(§1)은 ① 서술 시점에 그 접두어 하위 라우트가 **1건 이상 존재** ② **서술 이후 도입된 엔드포인트**가 **동일 노출 면**임을 모순 검사로 확인 — 두 조건 충족 시만 예외. `라우트 무변경` 행이 막는 **신규 엔드포인트**(이 PR 에서 라우트가 추가된 경우)와는 다른 대상이다 |
| **모순 검사** (리뷰어 의무) | 레포 내 **닫힌 목록 3종** 확인 — (1) 공개 라우터·게이트웨이 라우트 등록 (2) 인증 예외·허용 목록 설정 (3) 핸들러의 공개 인증 어노테이션 |
| **모순 검사 — 결과** | 하나라도 모순 시 fail-closed → **E 재판정** + §5 원장에 `문서 근거 오판:` 기록. 비용은 레포 내 검색 3종이며, **레포 내 반증 가능 범위에 한해** 신선도를 보완한다 — `격리` 가 레포 밖 설정으로만 성립하면 보강 수단이 없음을 리뷰 본문에 명기 |
| **모집단** | **현상 서술 문서**(README·운영 문서)만. 기획·제안 문서(PRD·research·ADR 제안)·코드 주석·PR 본문은 제외 — **현재 시제 현상 서술만** 인정하며 "제한할 예정" 류 계획 서술은 증거가 아니다 |
| **레포 밖 불인정** | 사내 위키·문서 전용 레포 페이지는 **구성상 항상 diff 밖**이어서 기준선 요건이 무의미하고 모순 검사 대상도 없다 → 레포 밖 근거는 **설정·코드 원문 발췌**만 (식별 정보 일반화 의무 동시 적용 → [`harness-infra-review.md`](harness-infra-review.md)) |
| **충족 불가 요소** | `계약` 의 "기록 위치" 는 문서·PR 본문·코드 주석 어디든 가능. 확인 형태에 "문서 서술" 표기가 **없는** `역할검사`·`호출측검증` 는 **문서로 충족 불가** |
| **상충·삭제** | 두 문서 또는 **선언 간**(코드 주석 `TRUST-BOUNDARY` ↔ 문서 서술) 노출 면이 상충하면 fail-closed → **E 재판정**. 노출 면 서술이 **삭제**되면 그에 근거한 기존 I·A 선언은 무효 |
| **모노레포** | "리뷰 대상 레포의 문서" = **해당 패키지·모듈 범위의 문서** |
| **전환기 — 서술 없는 레포** | 종전과 동일 — 원문 근거 또는 **E** |
| **전환기 — 검토 범위** | 레포 전역 **탐색 의무는 없으나**, [9-코드] 는 스킬 (a) 공급 범위(`README.md` + PR 본문이 지목한 문서) 내 서술은 **반드시 검토**(리뷰어별 판정 비결정성 차단) |
| **전환기 — 발효 이전 서술** | 본 완화 머지 커밋 이전 서술도 문서 근거로 쓴다. 단 `(미검증 — 5a 근거 불가)` **표기 부재가 §5 심사 통과를 뜻하지 않는다** — 모순 검사 결과로만 판정한다 |

위 요건이 절 표제의 "자가 선언 불가" 를 문서 경로에서 유지하는 장치다.

### 흔한 오판 2종

| 오판 | 실제 |
|------|------|
| 전송 계층 인증(mTLS 등)이 있으니 인가도 된다 | 인증은 **호출 워크로드의 신원**만 확립한다. 누가 호출해도 되는지는 별도 인가 설정이 정한다 |
| peer 신원에서 사용자 주체를 얻을 수 있다 | peer 신원은 **워크로드 신원**이며 최종 사용자 주체를 대체하지 못한다. 판정행 1 의 "인증 컨텍스트에서 주체 추출" 을 peer 신원으로 충족했다고 판단 금지 |

**설정 존재 ≠ 적용**: 정책 파일이 있다는 사실과 그것이 이 엔드포인트에 **실제로 적용되고 기본 거부인가** 는 다르다. "라우트를 만들지 않았다" 같은 **부정 진술은 증거가 아니다.**

### 선언 형식

| 등급 | 형식 |
|:----:|------|
| I | `TRUST-BOUNDARY: I + <격리증거> + <인가증거> + <계약위치> + <적용환경범위>` |
| I (2·4b 해제 시) | 위 형식 + `+ <호출측검증위치>` |
| A | `TRUST-BOUNDARY: A + <인증설정위치> + <역할검사위치> + <적용환경범위>` |
| I·A (`문서 근거`) | 별도 서식 없음 — **기준선** 문서 서술(엔드포인트 식별 가능) + 리뷰 본문의 `문서 근거 완화:` 1줄 |

리뷰어는 리뷰 본문에 "확인한 위치(파일·줄·설정 경로, 문서는 파일·섹션)" 를 인용해야 완화 인정.

> **선언 무효 (절차, 점수 아님)**: 증거 요소 중 하나라도 **결손**되거나 **근거(원문·문서 서술) 열람 불가**면 I·A 선언은 무효이며 **E 기준으로 재판정**한다. 판정표는 등급이 확정된 뒤 적용한다.

**⛔ fail-closed**: 리뷰어가 해당 **근거(설정·코드 원문 또는 문서 서술)** 의 **내용을 직접 읽고 조건 충족을 인용할 수 없으면 부재로 간주**한다. 리뷰 대상 레포 밖 설정·코드 증거는 **PR 본문 원문 발췌** 또는 **레포 내 문서 서술** 중 하나로 충족한다 (발췌 시 식별 정보 일반화 의무 동시 적용 → [`harness-infra-review.md`](harness-infra-review.md)). 어느 쪽도 없이 **경로·파일명만 제시된 증거는 불인정**.

**환경 범위 · 유효기간**: 선언은 **코드·문서**에 상주하지만 참·거짓은 **환경 설정**이 결정한다. 환경별 노출 면이 다르면 **환경별 개별 선언**. 노출·인가 설정을 바꾸는 변경이 발생하면 기존 선언은 무효다. 문서 서술이 **현재 설정과 어긋나는 것이 관측되면** 그 서술은 즉시 무효다. 무효화 관측 시점은 리뷰어에 귀속한다 — 해당 엔드포인트를 수정하는 PR 에서 **리뷰어가 선언의 환경 범위 유효성을 재확인**하고 재판정한다. 일괄 소급 없음.

## 3. 판정표 (단일 SSOT)

한 행 = 한 판정. **적중 조건이 성립하고** 해당 등급 칸이 **적용**인데 **필수 방어가 없으면** 적중이며, 그 행의 상한이 보안 점수에 걸린다. 적중 조건 자체가 성립하지 않으면(해당 입력을 받지 않는 엔드포인트 등) 적중이 아니다.

**등급 칸 어휘**: `적용` = 적중 대상 / `해제` = 미적중 / `조건부`·`중첩 시 적용` = 표 아래 각주 조건으로 적용·미적중을 확정.

| # | 적중 조건 | 필수 방어 | E | I | A | 보안 상한 |
|:-:|-----------|-----------|:-:|:-:|:-:|:---------:|
| 1 | 신원·권한 주체를 경계 바깥 파라미터로 수신 | 인증 컨텍스트에서 주체 추출. 타인 지정은 별도 관리자 엔드포인트 + 권한 검사 | 적용 | 해제 | 해제 | **3** |
| 2 | 리소스 참조 시 소유권 결합 미검증 | 조회 쿼리에 소유자 조건 결합 — 조회 후 분기가 아닌 **쿼리 단계 결합** | 적용 | 조건부 | 적용 | **6** |
| 3 | 권한·등급·금액을 경계 바깥이 전달 | 서버 조회값 사용. 요청 바디의 해당 필드는 **무시 또는 거부** | 적용 | 해제 | 적용 | **6** |
| 4a | 대량 처리 **범위 상한** 부재 | 서버측 범위 상한 | 적용 | 적용 | 적용 | **6** |
| 4b | 대량 처리 **전건 소유권 검증** 부재 | 대상 전건 소유권·권한 검증 | 적용 | 조건부 | 적용 | **6** |
| 5 | 미검증 열거 가능 식별자 노출 | 소유권 검증 선행 시 허용. 검증 없는 열거 가능 ID 노출 금지 | 적용 | 해제 | 적용 | **6** |
| 6 | 역할·스코프 미검사 (인증은 수행하나 역할·스코프 검사가 없음) | 역할·스코프 검사 | 중첩 시 적용 | 해제 | 적용 | **6** |

**6행의 E 중첩**: 인터넷 노출 admin 콘솔은 §1 중간 형태 규칙에 따라 E 확정이되 A 의 역할 검사 요건이 중첩된다 — 이 경우에만 6행이 E 에서 적중하며, 판정 근거는 A 선언 증거가 아니라 **핸들러 코드**다.

**조건부 (I 등급의 2·4b)**: 주체 식별자가 파라미터로 **함께 전달되면 적용**한다 — 피호출측이 소유권 결합을 수행할 수 있고 수행해야 한다. 호출측이 최종 사용자가 조작한 리소스 ID 를 검증 없이 relay 하면 타인 리소스가 반환되기 때문이다(혼동된 대리자). 주체가 전달되지 않아 **결합 자체가 불가능한 경우에 한해 해제**하며, 이때도 **`호출측검증` 증거의 원문 발췌 제시가 필수** — 미제시 시 해제 불가.

**4a 가 전 등급 적용인 이유**: 신뢰 경계 문제가 아니라 **blast radius 통제**다. 신뢰된 호출측의 버그·오작동 하나로 전건이 삭제·변조되는 것을 막는다.

**문서 근거 하향 (§2 — 보고용)**: 등급이 `문서 근거`로 확정되면 적중 행의 보안 상한에서 **1 을 뺀다** (6→5, 3→2). 복수 적중 시 가장 낮은 상한을 채택한 **뒤** 하향한다. 적중 행 상한은 어느 쪽이든 6 이하이므로 **이 하향은 통과·미달 판정을 바꾸지 않는 심각도 신호**이며, §4 의 I 등급 구조적 상한 7 도 **하향 대상이 아니다**. 문서 근거 경로의 실질 억제는 **기준선 문서 요건(§2) + 리뷰 본문 인용 의무 + 사후 관측(§5)** 이 담당한다.

**복수 적중**: 같은 항목(5 보안)에 여러 행이 적중하면 **가장 낮은 상한**을 채택한다 — [`harness-code-review.md`](harness-code-review.md) "합성 규칙".

**용어**: **주체 식별자** = 인가 판단에 직접 쓰이는 principal 식별자(사용자·테넌트 등). **파라미터** = path·query·body·header 전부, 중첩 DTO 필드 포함.

## 4. 8점 질문

> **E·A:** 경계 바깥에서 모든 파라미터를 임의 값으로 바꿔 보내도 타인 리소스 접근·권한 상승·금액 조작이 불가능한가? → 답이 코드에 있으면 8+
>
> **I:** **허용 목록에 포함된 내부 워크로드가 침해되었을 때**, 그 호출자의 도달 범위가 **원래 정당하게 접근 가능한 범위로 제한**되는가? → lateral movement 기준.
>
> 답은 **피호출측 코드**에서 찾는다 — `호출측검증` 증거는 침해 전제에서 무효이므로 답이 될 수 없다. 허용 목록 **밖** 호출자는 `인가` 증거가 이미 차단하므로 그 답도 증거의 재확인일 뿐이다.
>
> **I 등급의 구조적 상한**: 판정행 1·3·5 해제 + 2·4b 를 호출측 전달 주체로 결합하는 설계에서는 침해된 호출자의 임의 주체 지정을 피호출측이 막을 수 없다. 사용자 리소스를 다루는 I 엔드포인트는 이 구조를 유지하는 한 **보안 7 이 상한**이며, 이는 완화의 대가로 감수하는 값이다 (미달 아님). `문서 근거`로 확정된 I 도 **동일하게 7** — §3 의 -1 하향은 적중 행에만 걸린다.

## 5. N/A · 관할 · 재검토

**N/A 선언**: 인증이 불요한 공개 리소스만 다루는 변경(읽기 전용 공개 데이터), 또는 **요청 주체·권한 개념 자체가 없는 변경**(라이브러리·CLI·빌드 스크립트·하네스 메타)은 N/A — 리뷰 본문에 "5a N/A: <이유>" 1줄 기록 후 skip. **⛔ 예외**: **실제 엔드포인트에 대한** 노출 면·허용 호출자 **서술을 신규 추가·수정하는 PR 은 N/A 불가**(서술 규칙·템플릿을 바꾸는 하네스 메타 PR 은 해당 없음) — 그 PR 에서 서술의 사실성을 설정·코드 원문으로 확인한다. **확인 불가 시 그 서술 옆에 `(미검증 — 5a 근거 불가)` 표기를 요구**하며, 미부착 시 그 서술은 증거로 쓸 수 없고 **High 이슈로 지적**한다. 리뷰 본문은 인-메모리라 후속 PR 에 도달하지 않으므로 **판정을 문서에 영속 각인**해야 한다 (§2 자유 형식 원칙의 예외는 이 미검증 케이스에 한정). 심사 없이 기준선을 획득하는 경로를 막는다. **I 등급과 혼동 금지** — I 는 "인증이 다른 계층에 있음", N/A 는 "인증 개념 자체가 없음".
