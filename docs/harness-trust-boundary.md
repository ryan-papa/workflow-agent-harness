# Harness: 신뢰 경계 판정 (코드 리뷰 5a SSOT)

코드 리뷰 보안 항목 **5a 파라미터 위변조 방지(BOLA/IDOR)** 의 단일 기준 문서. 점수 체계·통과 조건은 [`harness-code-review.md`](harness-code-review.md) 가 SSOT 이며, 본 문서는 **무엇이 적중이고 상한이 얼마인가** 를 정의한다.

## 원칙

신원·권한·등급·금액 등 **결과를 좌우하는 값은 신뢰 경계 안쪽에서 결정**한다. 경계 바깥이 보내는 파라미터는 "무엇을 요청하는지" 만 전달하고 "그럴 자격이 있는지" 는 전달하지 않는다.

**인증 컨텍스트** = 세션·JWT 클레임·서버 세션 스토어 등 **호출자가 변조 불가능한 출처**. 스택 독립.

## 1. 노출 등급 (선행 판정)

5a 적용 전 대상 **엔드포인트(핸들러 메서드)** 의 등급을 확정한다.

| 등급 | 정의 | 경계 바깥 |
|:----:|------|-----------|
| **E** External | 외부 공개 — 대고객 앱·웹·퍼블릭 API | 최종 사용자·외부 조직 |
| **I** Internal | 내부 전용. 외부 미노출 + **호출자 인가 확립(계층 무관)**. 주체 결정은 호출측 서비스 책임 | 동일 신뢰 도메인의 다른 워크로드 |
| **A** Admin | 인증된 운영자 전용 | 인증된 운영자 |

**미선언 시 기본값 = E** (보수적 판정).

| 중간 형태 | 확정 등급 |
|-----------|-----------|
| 모바일 앱 전용 · 파트너 전용 API | **E** — 경계 바깥에 최종 사용자·외부 조직이 있으면 호출자 인가 확립 여부와 무관 |
| 인터넷 노출 admin 콘솔 | **E** 확정 + A 의 역할 검사 요건 **중첩 적용** |
| 한 컨트롤러에 노출 면이 다른 핸들러 혼재 | 클래스 단위 금지 — **엔드포인트 단위 개별 판정** |

**선언 단위 = 엔드포인트.** 클래스 주석·PR 본문·프로젝트 문서 **어디에 기록하든 적용 대상 엔드포인트를 명시 열거**한다. 열거 없는 일괄 선언은 무효. 경로 접두어·와일드카드 서술(`/internal/**` 등)은 **대상 엔드포인트의 포함이 식별 불가할 때만** 닫힌 목록 `대상 불명`(§2)에 해당한다 — **확인 미수행 자체는 불인정 사유가 아니다**. **라우트 존재 임계**(접두어 하위 라우트 1건 이상)는 §2 `선행(예고) 서술` 행이 단독 보유한다.

## 2. 증거 (I·A — 근거 제시 필요)

증거는 **이름**으로 식별한다 (선언 형식의 플레이스홀더와 동일). 번호를 쓰지 않는 이유는 등급마다 요소 구성이 달라 같은 번호가 다른 대상을 가리키기 때문이다.

| 등급 | 증거 | 입증할 사실 | 확인 형태 |
|:----:|------|-------------|-----------|
| **I** | `격리` | 해당 엔드포인트가 **외부에서 도달 불가** | 설정 원문 **또는 문서 서술** |
| **I** | `인가` | **허용 호출자가 열거**되고 그 밖은 기본 거부 | 설정 원문 **또는 문서 서술** |
| **I** | `계약` | 주체 결정 책임이 **호출측**에 있음 | 기록 위치 |
| **I** 조건부 | `호출측검증` | **호출측 소유권 검증 지점** — 판정행 2·4b 를 해제할 때만 요구 | 검증 코드 **원문 발췌** (문서 서술 불인정) |
| **A** | `인증설정` | 해당 경로를 덮는 인증 설정 | 파일·줄 **또는 문서 서술** |
| **A** | `역할검사` | 역할·스코프 검사 코드 | 파일·줄 |
| **I·A** | `환경범위` | 선언이 유효한 환경 | 원문 근거: **`격리`·`인가`(A 는 `인증설정`) 원문 내에서 식별 가능한** 환경 식별자 — 파일 경로·네임스페이스·프로파일 키 등 / 문서 근거: 문서가 **환경별 노출 면을 구분 서술**하거나 **적용 환경을 명시 열거**("운영·스테이징 동일" 등 전 환경 동일 표기 포함). **근거 유형 무관** — 환경 언급·식별자가 전혀 없으면 **프로덕션 한정 선언**으로 좁혀 읽고 그 밖 환경은 **미선언**(E). 침묵을 전 환경 충족으로 읽지 않으며, 이 범위에서는 `요소 결손` 이 아니다 |

**수단은 스택 자유** — 서비스 메시 정책·API 게이트웨이 허용목록·사설 서브넷·방화벽 규칙 무엇이든 무방하다. 판정 기준은 "무엇을 썼는가" 가 아니라 **위 사실이 리뷰어가 읽을 수 있는 근거로 확인되는가** 이다.

### 근거 유형 2종

| 유형 | 충족 수단 | 적중 행 상한 | 리뷰 본문 의무 |
|------|-----------|:------------:|----------------|
| `원문 근거` | 확인 형태에 **"문서 서술" 대안이 있는 요소 전부**(`격리`·`인가`·`인증설정`·`환경범위`)가 설정·코드 원문(파일·줄)으로 확인 | 판정표 값 그대로 | 확인한 파일·줄·설정 경로 인용 |
| `문서 근거` | **요소 하나라도 문서 서술로 충족**(= `원문 근거` 의 여집합 전부) | **동일** — 하향 없음 | 위 + `문서 근거: <파일·섹션> "<인용 문장>"` 1줄 |

두 유형은 **판정에서 동급**이다. 유형 구분은 리뷰 본문에 무엇을 인용할지만 가른다.

**문서 서술** = 리뷰 대상 레포의 **문서 파일**(`README.md`·`docs/` 등. **같은 PR 에서 추가·수정한 파일 포함**. 코드 주석은 문서 서술이 아니다)에서 해당 엔드포인트의 **노출 면·허용 호출자 범위**를 서술한 산문·표. 표기 대응: **내부 전용 = I · 대고객 = E · 운영자 = A**. **자유 형식** — 전용 섹션·고정 서식 불요. 별도 `TRUST-BOUNDARY` 선언이 없어도 **서술 자체를 선언으로 인정**하되 §1 선언 단위 규칙은 그대로 적용된다 — 서술에서 **적용 엔드포인트가 식별 가능**해야 하며, 식별 불가한 일괄 서술은 무효다.

#### ⛔ 진실 추정 (기본 원칙)

문서에 서술된 노출 면은 **참으로 추정**한다. 리뷰어는 서술을 신뢰하고 판정하며, **"문서라서 신뢰할 수 없다"·"설정으로 확인되지 않았다" 류 일반 논거로 E 재판정할 수 없다**. 불인정은 아래 **닫힌 목록 6종**의 사유에 해당할 때만 가능하고, 리뷰어는 **어느 사유인지 + 그 근거 원문**을 리뷰 본문에 인용해야 한다. 인용 없는 불인정은 **무효이며 서술대로 판정**한다. **부재형 사유**(`요소 결손`·`대상 불명`)는 인용할 원문이 없으므로 **검토한 서술 원문 + 결손·불명 요소의 명시**로 인용 의무를 충족한다.

| 불인정 사유 (닫힌 목록) | 성립 조건 |
|-------------------------|-----------|
| **선행(예고) 서술** | **리뷰 시점**(PR 적용 후) 레포에 그 엔드포인트의 **라우트 매핑이 부재** — 존재하지 않는 대상에 대한 예고는 현상 서술이 아니다. 같은 PR 에서 서술과 라우트를 함께 추가했으면 **부재가 아니다**. 와일드카드 서술은 접두어 하위 라우트가 1건 이상 존재하면 해당 없음. **git 이력 불요** |
| **모순 발견** | 레포 내 라우트 등록·인가 설정·인증 어노테이션에서 **서술과 어긋나는 사실을 실제로 발견**(아래 반증 절차) |
| **상충·삭제** | 두 문서 또는 선언 간(코드 주석 `TRUST-BOUNDARY` ↔ 문서) 노출 면이 상충 / 근거 서술이 **삭제**됨 |
| **대상 불명** | 서술에서 **적용 엔드포인트를 식별할 수 없음**(§1 선언 단위) |
| **계획 서술** | 서술이 **미래 시제**("내부 전용으로 제한할 예정" 등) — 현상 서술이 아니므로 §2 모집단 비해당 |
| **요소 결손** | **해당 등급이 요구하는 증거 요소**(§2 표 — I: `격리`·`인가`·`계약` / A: `인증설정`·`역할검사` / 공통 `환경범위`) 중 서술에도 원문에도 **아무 근거가 없는** 요소가 있음. 단 `환경범위` 는 §2 표의 **좁혀 읽기 규칙이 우선**하며(근거 유형 무관) 프로덕션 범위에서는 결손이 아니다 |

#### 반증 절차 (의무 아님)

모순 검사는 **반증 수단**이며 수행 의무가 아니다 — **미수행 자체는 불인정 사유가 아니다**. 리뷰어가 의심하면 레포 내 (1) 공개 라우터·게이트웨이 라우트 등록 (2) 인증 예외·허용 목록 설정 (3) 핸들러의 공개 인증 어노테이션을 확인하고, **모순을 발견한 경우에만** E 재판정 + §5 원장에 `문서 근거 오판:` 기록한다. `격리` 가 레포 밖 설정으로만 성립해 반증 수단이 없으면 **서술대로 판정**하고 원장에 `반증불가:` 로 기록한다(관측용).

#### 문서 서술의 범위

| 항목 | 내용 |
|------|------|
| **작성 시점** | **같은 PR 에서 추가·수정한 서술도 인정**한다. 기준선(머지 완료) 요건 없음 |
| **모집단** | **레포에 커밋된 문서 파일**(`README.md`·`docs/`·운영 문서)의 **현상 서술**(현재 시제). **PR 본문·코드 주석은 제외** — 레포 산출물이 아니어서 후속 PR 에서 `상충·삭제` 검출이 불가하다. "제한할 예정" 류 **계획 서술도 제외** |
| **레포 밖 문서** | 사내 위키·문서 전용 레포 페이지는 **불인정** — 리뷰 대상 레포 밖 근거는 설정·코드 **원문 발췌**만 (식별 정보 일반화 의무 동시 적용 → [`harness-infra-review.md`](harness-infra-review.md)) |
| **모노레포** | "리뷰 대상 레포의 문서" = 해당 패키지·모듈 범위의 문서 |
| **충족 불가 요소** | `계약` 의 "기록 위치" 는 문서·PR 본문·코드 주석 어디든 가능. 확인 형태에 "문서 서술" 표기가 **없는** `역할검사`·`호출측검증` 는 **문서로 충족 불가** |
| **검토 범위** | 레포 전역 탐색 의무는 없으나, [9-코드] 는 스킬 (a) 공급 범위(`README.md` + PR 본문이 지목한 문서) 내 서술은 **반드시 검토**한다 (리뷰어별 판정 비결정성 차단) |
| **서술 없는 레포** | 종전과 동일 — 원문 근거 또는 **E** |

### 흔한 오판 2종

| 오판 | 실제 |
|------|------|
| 전송 계층 인증(mTLS 등)이 있으니 인가도 된다 | 인증은 **호출 워크로드의 신원**만 확립한다. 누가 호출해도 되는지는 별도 인가 설정이 정한다 |
| peer 신원에서 사용자 주체를 얻을 수 있다 | peer 신원은 **워크로드 신원**이며 최종 사용자 주체를 대체하지 못한다. 판정행 1 의 "인증 컨텍스트에서 주체 추출" 을 peer 신원으로 충족했다고 판단 금지 |

**설정 존재 ≠ 적용**: 정책 파일이 있다는 사실과 그것이 이 엔드포인트에 **실제로 적용되고 기본 거부인가** 는 다르다. "라우트를 만들지 않았다" 같은 **부정 진술은 원문 근거가 되지 못한다** — 이 문장은 설정·코드 원문 경로에만 적용되며, **노출 면 문서 서술에는 적용하지 않는다**(§2 진실 추정).

### 선언 형식

| 등급 | 형식 |
|:----:|------|
| I | `TRUST-BOUNDARY: I + <격리증거> + <인가증거> + <계약위치> + <적용환경범위>` |
| I (2·4b 해제 시) | 위 형식 + `+ <호출측검증위치>` |
| A | `TRUST-BOUNDARY: A + <인증설정위치> + <역할검사위치> + <적용환경범위>` |
| I·A (`문서 근거`) | 별도 서식 없음 — 문서 서술(엔드포인트 식별 가능) + 리뷰 본문의 `문서 근거:` 1줄 |

리뷰어는 리뷰 본문에 "확인한 위치(파일·줄·설정 경로, 문서는 파일·섹션)" 를 인용해야 완화 인정.

> **선언 무효 (절차, 점수 아님)**: 위 **닫힌 목록 사유**에 해당하면 I·A 선언은 무효이며 **E 기준으로 재판정**한다. 판정표는 등급이 확정된 뒤 적용한다.

**fail-closed 의 적용 범위**: 리뷰어가 **아무 근거도 읽을 수 없을 때**(서술·원문 모두 부재, 경로·파일명만 제시) 부재로 간주한다. **읽을 수 있는 서술이 있으면 진실 추정이 우선**하며, 불인정은 닫힌 목록 사유 + 원문 인용으로만 가능하다.

**환경 범위 · 유효기간**: 선언은 **코드·문서**에 상주하지만 참·거짓은 **환경 설정**이 결정한다. 환경별 노출 면이 다르면 **환경별 개별 선언**. 노출·인가 설정 변경으로 **서술이 현재 설정과 어긋나게 된 것이 관측되면**(= 닫힌 목록 `모순 발견`) 그 선언은 무효다 — 설정이 바뀌었다는 사실 자체가 무효 사유는 아니다. **같은 PR 에서 서술과 설정을 함께 도입한 경우는 해당 없다.** 무효화 관측 시점은 리뷰어에 귀속한다 — 해당 엔드포인트를 수정하는 PR 에서 **리뷰어가 선언의 환경 범위 유효성을 재확인**하고 재판정한다. 일괄 소급 없음.

## 3. 판정표 (단일 SSOT)

한 행 = 한 판정. **적중 조건이 성립하고** 해당 등급 칸이 **적용**인데 **필수 방어가 없으면** 적중이며, 그 행의 상한이 보안 점수에 걸린다. 적중 조건 자체가 성립하지 않으면(해당 입력을 받지 않는 엔드포인트 등) 적중이 아니다.

**등급 칸 어휘**: `적용` = 적중 대상 / `해제` = 미적중 / `조건부`·`중첩 시 적용` = 표 아래 각주 조건으로 적용·미적중을 확정.

| # | 적중 조건 | 필수 방어 | E | I | A | 보안 상한 |
|:-:|-----------|-----------|:-:|:-:|:-:|:---------:|
| 1 | 신원·권한 주체를 경계 바깥 파라미터로 수신 | 인증 컨텍스트에서 주체 추출. 타인 지정은 별도 관리자 엔드포인트 + 권한 검사 | 적용 | 해제 | 해제 | **3** |
| 2 | 리소스 참조 시 소유권 결합 미검증 | 조회 쿼리에 소유자 조건 결합 — 조회 후 분기가 아닌 **쿼리 단계 결합** | 적용 | 조건부 | 적용 | **6** |
| 3 | 권한·등급·금액을 경계 바깥이 전달 | 서버 조회값 사용. 요청 바디의 해당 필드는 **무시 또는 거부** | 적용 | 해제 | 적용 | **6** |
| 4a | 대량 처리 **범위 상한** 부재 | 서버측 범위 상한 | 적용 | 적용 | 적용 | **6** |
| 4b | 대량 처리 **전건 소유권 검증** 부재 | 대상 전건 소유권·권한 검증 | 적용 | 조건부 | 적용 | **6** |
| 5 | 미검증 열거 가능 식별자 노출 | 소유권 검증 선행 시 허용. 검증 없는 열거 가능 ID 노출 금지 | 적용 | 해제 | 적용 | **6** |
| 6 | 역할·스코프 미검사 (인증은 수행하나 역할·스코프 검사가 없음) | 역할·스코프 검사 | 중첩 시 적용 | 해제 | 적용 | **6** |

**6행의 E 중첩**: 인터넷 노출 admin 콘솔은 §1 중간 형태 규칙에 따라 E 확정이되 A 의 역할 검사 요건이 중첩된다 — 이 경우에만 6행이 E 에서 적중하며, 판정 근거는 A 선언 증거가 아니라 **핸들러 코드**다.

**조건부 (I 등급의 2·4b)**: 주체 식별자가 파라미터로 **함께 전달되면 적용**한다 — 피호출측이 소유권 결합을 수행할 수 있고 수행해야 한다. 호출측이 최종 사용자가 조작한 리소스 ID 를 검증 없이 relay 하면 타인 리소스가 반환되기 때문이다(혼동된 대리자). 주체가 전달되지 않아 **결합 자체가 불가능한 경우에 한해 해제**하며, 이때도 **`호출측검증` 증거의 원문 발췌 제시가 필수** — 미제시 시 해제 불가.

**4a 가 전 등급 적용인 이유**: 신뢰 경계 문제가 아니라 **blast radius 통제**다. 신뢰된 호출측의 버그·오작동 하나로 전건이 삭제·변조되는 것을 막는다.

**복수 적중**: 같은 항목(5 보안)에 여러 행이 적중하면 **가장 낮은 상한**을 채택한다 — [`harness-code-review.md`](harness-code-review.md) "합성 규칙".

**용어**: **주체 식별자** = 인가 판단에 직접 쓰이는 principal 식별자(사용자·테넌트 등). **파라미터** = path·query·body·header 전부, 중첩 DTO 필드 포함.

## 4. 8점 질문

> **E·A:** 경계 바깥에서 모든 파라미터를 임의 값으로 바꿔 보내도 타인 리소스 접근·권한 상승·금액 조작이 불가능한가? → 답이 코드에 있으면 8+
>
> **I:** **허용 목록에 포함된 내부 워크로드가 침해되었을 때**, 그 호출자의 도달 범위가 **원래 정당하게 접근 가능한 범위로 제한**되는가? → lateral movement 기준.
>
> 답은 **피호출측 코드**에서 찾는다 — `호출측검증` 증거는 침해 전제에서 무효이므로 답이 될 수 없다. 허용 목록 **밖** 호출자는 `인가` 증거가 이미 차단하므로 그 답도 증거의 재확인일 뿐이다.
>
> **I 등급의 구조적 상한**: 판정행 1·3·5 해제 + 2·4b 의 **필수 방어를 호출측이 전달한 주체로 충족(= 미적중)** 한 설계에서는 침해된 호출자의 임의 주체 지정을 피호출측이 막을 수 없다. 사용자 리소스를 다루는 I 엔드포인트는 이 구조를 유지하는 한 **보안 8 이 상한**이다 — 보안 항목에는 감점형 규칙이 걸리지 않으므로(감점형은 1·2·7 전용) 이 상한은 **최저 축(≥7)이 아니라 평균 축(≥8.0)에 기여**한다. 9~10 을 주지 않는 것은 침해된 호출자의 임의 주체 지정을 피호출측이 막지 못한다는 구조적 사실의 표시다. `원문 근거`·`문서 근거` 동일 적용.
