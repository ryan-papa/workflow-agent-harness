# Harness: 신뢰 경계 판정 (코드 리뷰 5a SSOT)

코드 리뷰 보안 항목 **5a 파라미터 위변조 방지(BOLA/IDOR)** 의 단일 기준 문서. 점수 체계·통과 조건은 [`harness-code-review.md`](harness-code-review.md) 가 SSOT 이며, 본 문서는 **무엇이 적중인가** 를 정의한다.

> **⛔ 5a 는 참고 항목이다.** 판정표 적중은 리뷰 본문의 `5a 참고:` 코멘트로만 남긴다. **점수 상한·통과 조건·재시도에 영향 없음** — 5a 적중만을 이유로 보안 항목을 감점하지 않는다(5a 밖 일반 보안 기준 감점은 종전대로). 완화 기록 → §5.

## 원칙

신원·권한·등급·금액 등 **결과를 좌우하는 값은 신뢰 경계 안쪽에서 결정**한다. 경계 바깥이 보내는 파라미터는 "무엇을 요청하는지" 만 전달하고 "그럴 자격이 있는지" 는 전달하지 않는다.

**인증 컨텍스트** = 세션·JWT 클레임·서버 세션 스토어 등 **호출자가 변조 불가능한 출처**. 스택 독립.

## 1. 노출 등급 (선행 판정)

5a 적용 전 대상 **엔드포인트(핸들러 메서드)** 의 등급을 확정한다.

| 등급 | 정의 | 경계 바깥 |
|:----:|------|-----------|
| **E** External | 외부 공개 — 대고객 앱·웹·퍼블릭 API | 최종 사용자·외부 조직 |
| **I** Internal | 내부 전용. 주체 결정은 호출측 서비스 책임 | 동일 신뢰 도메인의 다른 워크로드 |
| **A** Admin | 인증된 운영자 전용 | 인증된 운영자 |

**기본값 = I.** 아래 확정 조건이 레포에서 **실제로 확인될 때만** E·A 로 판정한다. 확인되지 않으면 I.

| 등급 | 확정 조건 (하나 이상) |
|:----:|-----------------------|
| **E** | (1) 퍼블릭 게이트웨이·ingress·공개 라우터에 해당 경로 등록 (2) 인증 예외·공개 설정(`permitAll`·공개 어노테이션 등) (3) README·docs 에 대고객·퍼블릭 API 로 **현재 시제** 서술(예정형 제외) (4) 같은 레포의 대고객 앱·웹 코드가 해당 엔드포인트 직접 호출 |
| **A** | (1) 운영자 인증 설정 또는 역할·스코프 검사 코드가 해당 엔드포인트에 확인 (2) 문서가 운영자 전용으로 **현재 시제** 서술 |

| 중간 형태 | 확정 등급 |
|-----------|-----------|
| 모바일 앱 전용 · 파트너 전용 API | **E** — 경계 바깥에 최종 사용자·외부 조직이 있으면 호출자 인가 확립 여부와 무관 |
| 인터넷 노출 admin 콘솔 | **E** 확정 + A 의 역할 검사 요건 **중첩 적용** |
| 한 컨트롤러에 노출 면이 다른 핸들러 혼재 | 클래스 단위 금지 — **엔드포인트 단위 개별 판정** |

리뷰 본문에 E·A 로 판정한 근거(파일·줄 또는 문서 파일·섹션)를 1줄 인용한다.

### 흔한 오판 2종

| 오판 | 실제 |
|------|------|
| 전송 계층 인증(mTLS 등)이 있으니 인가도 된다 | 인증은 **호출 워크로드의 신원**만 확립한다. 누가 호출해도 되는지는 별도 인가 설정이 정한다 |
| peer 신원에서 사용자 주체를 얻을 수 있다 | peer 신원은 **워크로드 신원**이며 최종 사용자 주체를 대체하지 못한다. 판정행 1 의 "인증 컨텍스트에서 주체 추출" 을 peer 신원으로 충족했다고 판단 금지 |

## 3. 판정표 (단일 SSOT)

한 행 = 한 판정. **적중 조건이 성립하고** 해당 등급 칸이 **적용**인데 **필수 방어가 없으면** 적중이며, 리뷰 본문에 `5a 참고: <행 번호> <위치> <개선 방향>` 코멘트를 남긴다. 적중 조건 자체가 성립하지 않으면(해당 입력을 받지 않는 엔드포인트 등) 적중이 아니다.

**등급 칸 어휘**: `적용` = 적중 대상 / `해제` = 미적중 / `조건부`·`중첩 시 적용` = 표 아래 각주 조건으로 적용·미적중을 확정.

| # | 적중 조건 | 필수 방어 | E | I | A | 중요도 |
|:-:|-----------|-----------|:-:|:-:|:-:|:------:|
| 1 | 신원·권한 주체를 경계 바깥 파라미터로 수신 | 인증 컨텍스트에서 주체 추출. 타인 지정은 별도 관리자 엔드포인트 + 권한 검사 | 적용 | 해제 | 해제 | **높음** |
| 2 | 리소스 참조 시 소유권 결합 미검증 | 조회 쿼리에 소유자 조건 결합 — 조회 후 분기가 아닌 **쿼리 단계 결합** | 적용 | 조건부 | 적용 | 중간 |
| 3 | 권한·등급·금액을 경계 바깥이 전달 | 서버 조회값 사용. 요청 바디의 해당 필드는 **무시 또는 거부** | 적용 | 해제 | 적용 | 중간 |
| 4a | 대량 처리 **범위 상한** 부재 | 서버측 범위 상한 | 적용 | 적용 | 적용 | 중간 |
| 4b | 대량 처리 **전건 소유권 검증** 부재 | 대상 전건 소유권·권한 검증 | 적용 | 조건부 | 적용 | 중간 |
| 5 | 미검증 열거 가능 식별자 노출 | 소유권 검증 선행 시 허용. 검증 없는 열거 가능 ID 노출 금지 | 적용 | 해제 | 적용 | 중간 |
| 6 | 역할·스코프 미검사 (인증은 수행하나 역할·스코프 검사가 없음) | 역할·스코프 검사 | 중첩 시 적용 | 해제 | 적용 | 중간 |

**6행의 E 중첩**: 인터넷 노출 admin 콘솔은 §1 중간 형태 규칙에 따라 E 확정이되 A 의 역할 검사 요건이 중첩된다 — 이 경우에만 6행이 E 에서 적중하며, 판정 근거는 **핸들러 코드**다.

**조건부 (I 등급의 2·4b)**: 주체 식별자가 파라미터로 **함께 전달되면 적용**한다 — 피호출측이 소유권 결합을 수행할 수 있고 수행해야 한다. 호출측이 최종 사용자가 조작한 리소스 ID 를 검증 없이 relay 하면 타인 리소스가 반환되기 때문이다(혼동된 대리자). 주체가 전달되지 않아 **결합 자체가 불가능하면 해제**하며, 호출측 소유권 검증 지점이 확인되면 코멘트에 함께 적는다.

**4a 가 전 등급 적용인 이유**: 신뢰 경계 문제가 아니라 **blast radius 통제**다. 신뢰된 호출측의 버그·오작동 하나로 전건이 삭제·변조되는 것을 막는다.

**복수 적중**: 적중 행마다 코멘트 1줄. 중요도 **높음**을 먼저 쓴다.

**용어**: **주체 식별자** = 인가 판단에 직접 쓰이는 principal 식별자(사용자·테넌트 등). **파라미터** = path·query·body·header 전부, 중첩 DTO 필드 포함.

## 4. 판단 질문 (참고 — 감점 근거 아님)

> **E·A:** 경계 바깥에서 모든 파라미터를 임의 값으로 바꿔 보내도 타인 리소스 접근·권한 상승·금액 조작이 불가능한가?
>
> **I:** **허용된 내부 워크로드가 침해되었을 때**, 그 호출자의 도달 범위가 **원래 정당하게 접근 가능한 범위로 제한**되는가? → lateral movement 기준. 답은 **피호출측 코드**에서 찾는다.

답이 "아니오" 면 `5a 참고:` 코멘트에 개선 방향을 적는다. 점수에는 반영하지 않는다.
