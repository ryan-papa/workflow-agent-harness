# rp-code-review

코드 리뷰 (7항목 평가). **메인 셀프 채점 절대 금지** — 해당 런타임 서브에이전트가 **코드 관점**으로 채점.

[9]는 **2축 병렬**이다: `[9-코드]`(본 스킬) ∥ `[9-인프라]`([`rp-infra-review.md`](rp-infra-review.md)). 두 서브에이전트를 **동일 메시지에서 동시 발사**하고, 통과는 두 축 AND 결합.

## 민감 정보 스캔 (전 유형 필수)

CLAUDE.md "민감 정보 금지" 규칙 위반을 커밋 전 자동 검출.

```bash
# 스테이지된 파일에서 금지 패턴 검색
git diff --cached | grep -iE \
  'password[[:space:]]*=|api[_-]?key[[:space:]]*=|secret[[:space:]]*=|token[[:space:]]*=|@[a-z0-9]+\.(com|net|org|kr)|age1[a-z0-9]{50,}'
```

발견 시 머지 차단 → 개발자 수정 후 재스캔.
개인 식별 정보(실명·개인 이메일 등)는 정적 패턴으로 검출이 어려우므로, 커밋 메시지·문서 제목은 별도 수동 검토 필요.

## 평가 항목 (코드 프로젝트, 각 10점)

정확성 / 설계 및 구조 / 가독성 / 테스트 품질 / 보안 / 성능 및 효율성 / 유지보수성 및 컨벤션

각 항목에 점수 구간별 기준 + "8점 판단 질문" 적용.

**점수 상한 규칙** (적중 시 해당 항목 상한 적용, 리뷰어 재량 완화 불가):

| 규칙 | 항목 | 상한 |
|------|------|:----:|
| 1a 동시성 방어책·포기 메모 부재 | 정확성 | 7 |
| 1b 프록시 self-invocation (피호출자 어드바이스 보유 + 같은 빈 `this.xxx()`) | 정확성 | 6 |
| 5a 판정표 적중 | 보안 | 적중 행의 `보안 상한` 열 값 (3 또는 6) |

상한 6 이하는 최저 기준(≥7)에 자동 미달 — **별도 FAIL 경로 없음**.

**합성 규칙**: 동일 항목에 상한 복수 적중 → **가장 낮은 상한** 채택. 상한 + 감점 동시 → **감점 먼저, 그 뒤 상한 클램프** (`min(원점수 - 감점, 상한)`).

**5a 선행 판정 — 노출 등급**: 대상 **엔드포인트**를 **E**(외부 공개) / **I**(내부 전용) / **A**(운영자 전용) 로 먼저 확정. **미선언 시 E 기본값.** I·A 는 `TRUST-BOUNDARY` 증거 필수이며, 결손 또는 **증거(설정·코드 공통) 원문 열람·인용 불가 시 fail-closed → E 재판정**. 등급 정의·증거 요건·판정표 전행 → SSOT [`../harness-trust-boundary.md`](../harness-trust-boundary.md).

## ⛔ 실행 주체 (서브에이전트 필수)

코드 리뷰는 **반드시 메인 런타임의 서브에이전트로 실행** (Claude-Lead=Agent 툴 `subagent_type=general-purpose` / Codex-Lead=`spawn_agent`). 메인 에이전트 셀프 채점 **금지**.

**병렬 발사**: [9] 진입 시 `[9-코드]`(7항목 점수제) 와 `[9-인프라]`(무점수 BLOCK/ASK/WARN) 서브에이전트를 **동일 메시지에서 동시 발사**한다. 컨텍스트 미공유 독립 판정. Codex-Lead 는 `spawn_agent` 동시 발사 불가 시 **순차 fallback 허용** (판정 규칙·통과 조건 동일).

**서브에이전트 프롬프트** 4 필수 항목 (a)~(d) → SSOT: [`../harness-absolute-rules.md`](../harness-absolute-rules.md) "[리뷰 단계 서브에이전트 필수]" 절. 본 단계 적용값: (a) 리뷰 대상 diff·브랜치·파일 경로 + **PR 본문(있을 경우) 및 `TRUST-BOUNDARY` 선언 원문** (b) 코드 축 = 7항목 + PR 유형별 포커스 / 인프라 축 = 5영역 무점수 판정 (c)·(d) SSOT 그대로.

**결과 처리**: 별도 파일 저장 없음. 서브에이전트 점수·지적은 인-메모리에서 메인이 수신 후 코드·PRD 본문·PR 노트에 반영.

**재시도**: PRD 본문 갱신 + 코드 수정 후 **미달·차단된 축만** 새 서브에이전트로 재실행. 회차별 별도 파일·점수 보존 없음 (한도는 아래 판정 절).

**조건부 재검증**: 수정이 상대 관점 영역을 건드리면 통과한 축도 1회 재검증 — SQL·Redis·직렬화 대상 타입·배포 매니페스트 변경 → 인프라 축 / 비즈니스 로직·공개 API·테스트 변경 → 코드 축. 재검증은 카운트 미소비, **같은 사이클 내 연쇄 재검증 금지**(미달 시 다음 사이클의 미달 축으로 전환).

**부분 기술 실패**: 한 축만 실패 시 해당 축만 최대 2회 재호출(총 3회), 정상 축 결과 보존. **실패 축을 생략한 통과 판정 금지**. SSOT [`../harness-absolute-rules.md`](../harness-absolute-rules.md) "재시도 한도" 적용. 메인 셀프 채점 우회 금지.

## 변경 영향 범위 테스트 검증 (필수)

요청 기능 외 변경으로 영향받은 영역(호출처·재사용 모듈·인접 분기 등)에 회귀 테스트가 추가되었는지 확인. 누락 시 항목 4(테스트 품질) **-1 감점**. 리뷰 미통과 사유로 직접 사용 가능.

## 판정 (2축 AND 결합)

**통과 조건 (모두 충족):**
- 코드 축: 평균 >= 8.0 AND 각 항목 >= 7
- 인프라 축: **BLOCK 0건 AND 미해결 ASK 0건** ([`rp-infra-review.md`](rp-infra-review.md))

최저 미달 시 평균 8.0 이상이어도 **미통과**. 코드 점수와 인프라 등급은 **독립 판정** — 서로의 점수를 조정하지 않는다. 관할 경계(중복 지적·상반 판정) → SSOT [`../harness-infra-review.md`](../harness-infra-review.md) "관할 경계".

**재시도:**
- 미달·차단 → 개발자 재투입 (인-메모리 **최대 5회** — 본 [9] 단계 한정, **코드+인프라 공통 카운터**. [4]·[5]는 축별 3회)
- **소비 단위 = 사이클** — 한 사이클에서 어느 축이든 1개 이상 재실행하면 1회 소비. 조건부 재검증은 미소비. ASK 발생 자체도 미소비(ASK 후 코드 수정하여 재실행하면 그 사이클이 1회 소비)
- **5회 미달 → 자동 중단 + 사용자 결정 요청** (강행/재설계/중단). 임계 완화 금지 — SSOT: [`../harness-absolute-rules.md`](../harness-absolute-rules.md) "재시도 한도"
